## 1. Quick Start: The One-Command Launch

To start the complete Upside-Down full-stack platform for local demonstration:

```bash
# In repository root:
npm run dev:all
```

This single command launches:
1. **Coordinator Host (Computer A):** `http://localhost:4000`
2. **Client-Local Offline Sync (Computer B):** `http://localhost:4100`
3. **Official Team Frontend:** `http://localhost:5173`

The launcher automatically frees required ports, verifies SQLite database directories, synchronizes security credentials, and displays color-coded logs in real time.

## 2. Live Demonstration Script for Hackathon Judges

### Step 1: Open the Application & Pair Browser (0:00 - 0:45)
1. Open Google Chrome or any modern browser to:  
   👉 **`http://localhost:5173/`**
2. When prompted for pairing, copy the pairing key displayed in your terminal output (or from `client-local/data/device-b.db.session.json`).
3. Click **Pair with Local Service**.
4. **Judge Takeaway:** Notice the green "Coordinator Connected" badge. The UI displays contract version `UD-IC/1.0`.

### Step 2: Create a Task & Observe Real-Time Sync (0:45 - 1:30)
1. Click **+ New Task** on the Task Board.
2. Enter:
   - **Title:** `Optimize SQL query execution in syncEngine`
   - **Description:** `Add compound index on (device_id, sequence)`
3. Click **Submit Command**.
4. **Judge Takeaway:** The task appears optimistically in the UI. In the terminal, observe `LOCAL-SYNC:4100` enqueuing the command into its SQLite WAL outbox, pushing to `COORDINATOR:4000`, and receiving an atomic ACK with Revision 1.

### Step 3: Simulate Network Partition & Offline Outbox (1:30 - 2:30)
1. Stop the Coordinator process (or disconnect network connectivity).
2. Look at the dashboard: The network badge transitions to amber ("Offline / Stale Read Mode").
3. While completely offline, click on the task and transition status to **`assigned`**.
4. **Judge Takeaway:** The command succeeds locally! The pending outbox count increments to 1. No network error modal interrupts the developer.
5. In your terminal, inspect the local SQLite WAL database:
   ```bash
   sqlite3 client-local/data/device-b.db "SELECT sequence, state, task_id FROM outbox;"
   ```
   The mutation is durably saved on disk with monotonic sequence 2.

### Step 4: Reconnect Network & Demonstrate Auto-Convergence (2:30 - 3:30)
1. Restart the Coordinator process (or reconnect network).
2. Within seconds, observe `LOCAL-SYNC:4100` reconnecting:
   - The worker automatically flushes the durable outbox.
   - The UI badge turns green ("Coordinator Connected").
   - The task status transitions to `assigned` at Revision 2.
3. **Judge Takeaway:** Zero data loss during partition. The authoritative coordinator committed the mutation exactly once.

### Step 5: Concurrency Conflict Quarantine & Human Resolution (3:30 - 4:30)
1. Navigate to the **Conflicts** tab in the dashboard.
2. Demonstrate how two concurrent edits against the same task revision do NOT result in "last-write-wins" silent corruption.
3. Show the open conflict record displaying the base revision, current revision, and peer payload.
4. As the lead engineer, click **Keep Authoritative** or **Apply Peer Transition**.
5. **Judge Takeaway:** Strict mathematical conflict protection with authorized human-in-the-loop governance.

### Step 6: AI Agent Patch Inspection & Two-Phase Application (4:30 - 5:30)
1. Navigate to **Patch Reviews**.
2. Select a proposed code patch generated by the AI Execution Engine.
3. Click **Download Patch** or inspect the highlighted unified diff view.
4. Click **Approve Patch** — notice that under `verified_application` mode, the task remains safely in `review`.
5. Click **Apply Patch** — observe the system verifying the diff hash checksum, running regression tests, creating a Git commit, and advancing the task to `done`.
6. **Judge Takeaway:** Production-grade safety. AI agents cannot commit unreviewed code directly to production repositories.

## 3. Physical Two-Computer Setup (Dikshant <-> Arhaan)

To run across two physical laptops on the same Wi-Fi network:

### Computer A (Dikshant — Coordinator Host)
1. Ensure inbound traffic on port 4000 is permitted:
   ```powershell
   New-NetFirewallRule -DisplayName "Upside-Down Coordinator" -Direction Inbound -LocalPort 4000 -Protocol TCP -Action Allow
   ```
2. Find your local IPv4 address:
   ```powershell
   ipconfig | findstr "IPv4"
   # Example output: 192.168.1.150
   ```
3. Start the coordinator:
   ```powershell
   .\scripts\start-coordinator.ps1
   ```

### Computer B (Arhaan — Offline Sync Node)
1. Start the client-local service targeting Computer A:
   ```powershell
   .\scripts\start-client-local.ps1 -CoordinatorUrl "http://192.168.1.150:4000"
   ```
2. Start the frontend:
   ```powershell
   .\scripts\start-frontend.ps1
   ```
3. Open `http://localhost:5173/` in your browser. All commands from Computer B replicate in real time to Computer A over the LAN.

## 4. Frontend Management & Rollback Operations

The platform supports hot-switching between the official team frontend and the backup demo cockpit:

```bash
# Check active frontend
npm run frontend:status

# Activate Official Team Frontend (web/)
npm run frontend:activate

# Rollback to Demo Cockpit (apps/demo-frontend/)
npm run frontend:rollback
```

Both frontends communicate with the same underlying SQLite WAL database and contracts without restarting the server.

## 5. Troubleshooting & Recovery Runbook

| Symptom | Cause | Remediation Command |
| :--- | :--- | :--- |
| `listen EADDRINUSE :4000` | Lingering Node.js process holding port | `powershell Stop-Process -Id (Get-NetTCPConnection -LocalPort 4000).OwningProcess -Force` |
| `CSRF_REQUIRED` on POST | Browser cookie missing or expired | Navigate to `http://localhost:5173/` and re-enter pairing key. |
| `CONTRACT_MISMATCH (426)` | Header `X-UD-Contract` missing | Ensure `client-local` is running latest `UD-IC/1.0` transport. |
| `REVIEWER_REQUIRED (403)` | Device token used for reviewer operation | Use official frontend or pass `Authorization: Bearer <reviewerToken>`. |
| Outbox not flushing | Coordinator unreachable | Check `http://localhost:4000/api/health` and verify network connectivity. |
